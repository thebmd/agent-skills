# 기업 해독기 (Company Decoder)

## 목적

개인 투자자가 가장 많이 하는 실수는 **모르는 기업에 투자하는 것**이다. 이 스킬은 어떤 기업이든 **10분 안에 이해할 수 있는 한 장 요약 카드**를 만든다.

**핵심 원칙**: 사업 모델이 가장 중요하다. 재무는 그 다음이다.

## 절대 규칙

1. **출력은 무조건 한국어.** 회계·금융 용어는 영문 병기 가능 (예: 영업이익(Operating Income), 잉여현금흐름(FCF)). 영문만 쓰지 않는다.
2. **출처 없는 숫자는 쓰지 않는다.**
   - 업로드된 자료 기반 → **페이지 번호까지 명시** (예: `출처: 10-K FY2024, p.62`)
   - 웹검색 기반 → **URL만 명시.** 페이지 번호를 추측해서 적지 않는다.
   - 확인 불가 → 숫자를 지어내지 말고 `확인 필요`라고 적는다.
3. **초등학생이 이해 못 하면 다시 쓴다.** 전문용어를 쓰면 반드시 괄호로 풀어준다.
4. **결과물은 아티팩트(artifact)로 만든다.** 채팅에 길게 늘어놓지 않는다.

## 입력 모드 (2단 구조)

### 모드 A — 티커만 (기본 · 빠름)

사용자가 티커/기업명만 준 경우. 웹검색으로 진행한다.

- 이 모드에서는 **페이지 출처를 적지 않는다.** URL만 단다.
- 카드 최상단에 표시: `📡 웹검색 기반 · 정확도를 높이려면 10-K(또는 사업보고서)를 업로드하세요`

### 모드 B — 자료 업로드 (정밀)

10-K, 20-F, 사업보고서 등이 업로드된 경우.

- **업로드 자료를 1순위 소스로 삼는다.** 웹검색은 보조(최신 주가, 최근 뉴스)로만.
- 페이지 출처를 반드시 명시한다.
- 카드 최상단에 표시: `📄 {문서명} 기반 · 페이지 출처 명시`

### 국가 자동 판별

- **미국 상장** → 10-K (연간보고서), 10-Q, 소스: SEC EDGAR
- **한국 상장** → 사업보고서, 분기보고서, 소스: DART (dart.fss.or.kr)
- 판별이 애매하면 사용자에게 한 번 묻는다.

## 요약 카드 구성 (이 순서를 지킨다)

### ① 2분 드릴 — 한 문장 (최상단, 가장 크게)

**이 카드의 심장.** 피터 린치의 2분 드릴: 이 회사가 뭘로 돈을 버는지 **초등학생도 이해할 수 있는 한 문장**으로.

작성 규칙:
- 한 문장. 두 문장이면 실패다.
- 업계 용어 금지. "플랫폼", "솔루션", "생태계" 같은 단어를 쓰면 실패다.
- "무엇을 만들어서 → 누구에게 → 어떻게 돈을 받는가"가 들어가야 한다.

좋은 예:
> **디즈니는 사람들이 사랑하는 캐릭터를 만들어서, 그 캐릭터 하나로 영화·구독료·장난감·놀이공원 입장료까지 평생 우려먹는 회사입니다.**

나쁜 예 (이러면 다시 쓴다):
> 디즈니는 미디어 및 엔터테인먼트 콘텐츠 제작과 배급, 테마파크 운영을 영위하는 글로벌 종합 엔터테인먼트 플랫폼 기업입니다.

### ② 돈 버는 구조 (그림)

**아티팩트 안에 SVG 또는 HTML 다이어그램으로 그린다.** 텍스트 나열 금지.

그림에 반드시 담을 것:
- **밸류체인**: 누구한테 사서(공급자) → 뭘 만들어서 → 누구한테 파나(고객) → 돈이 어디로 흐르나
- 각 화살표에 **돈의 방향**과 **금액/비중** (알 수 있으면)
- 순환 구조가 있으면 순환으로 그린다 (예: 디즈니 캐릭터 → 영화 → 굿즈 → 파크 → 다시 캐릭터 강화)

시각 규칙:
- 색은 3개 이하. 검정 + 파랑 계열 + 강조색 1개
- 박스 안 텍스트는 한국어, 5단어 이내
- 한눈에 안 들어오면 실패. 요소 7개를 넘기지 않는다.

### ③ 매출 구성 — 두 축으로

**반드시 두 축 모두** 보여준다. 표 + 간단한 막대/파이 그래프.

| 축 | 내용 |
|---|---|
| **사업부문별** | 각 부문 매출, 비중(%), 영업이익률. "어디서 벌고 어디서 까먹나"가 보여야 함 |
| **지역별** | 국가/지역별 매출 비중. 해외 비중이 높으면 → 환율·지정학 리스크 한 줄 코멘트 |

지역별 데이터가 공시에 없으면 `공시 미제공`이라고 적는다. 추정하지 않는다.

### ④ 고객 & 경쟁사

- **고객**: 누가 돈을 내나. B2C/B2B, 고객 집중도(특정 고객 매출 비중이 10% 넘으면 반드시 표시 — 리스크다)
- **경쟁사**: 3개. 각 1줄로 "얘랑 뭐가 다른가"

### ⑤ 이 업종의 핵심 KPI (1~2개)

**이 기업만의 진짜 지표**를 찾아서 5년(최소 3년) 추이를 보여준다. 매출·이익 같은 일반 지표 말고.

업종별 예시:
- 소매/외식 → 동일점포매출 성장률(Same-Store Sales)
- 스트리밍 → 구독자 수, 가입자당 평균 매출(ARPU), 이탈률(Churn)
- 테마파크 → 방문객 수, 1인당 지출(Per Capita Spending)
- 반도체 → 가동률, 재고자산회전율
- 은행 → 순이자마진(NIM), 연체율
- SaaS → 순매출유지율(NRR), 고객획득비용(CAC)

**KPI를 왜 봐야 하는지 한 줄 설명을 반드시 붙인다.** (예: "동일점포매출은 새 매장 여는 걸로 매출을 부풀렸는지 아닌지를 걸러내는 지표입니다.")

### ⑥ 경영진 & 오너십 (짧게 · 3줄 이내)

- CEO 이름, 재임 기간, 이전 경력 한 줄
- 창업자가 아직 관여하나?
- 내부자 지분율 / 주요 주주 (한국 기업이면 지배구조 한 줄)

### ⑦ 주주환원

- **배당**: 배당수익률, 배당성향, 연속 증배 연수
- **자사주**: 최근 3년 매입 금액, 실제 주식수가 줄었나 (매입해도 임직원 보상으로 다시 늘면 의미 없음 — 이걸 체크한다)

### ⑧ 이 회사가 망하는 시나리오 (한 줄) → 리스크 3개

**순서 엄수.** 망하는 시나리오가 먼저 나오고, 그 다음 리스크다.

- **망하는 시나리오 한 줄**: 리스크 나열이 아니라 **이야기**로. 
  > 예: "사람들이 더 이상 디즈니 캐릭터에 감정을 느끼지 않게 되는 순간, 이 회사의 모든 사업이 동시에 무너집니다."
- **리스크 3개**: 딱 3개. 각 1~2줄. 공시 Risk Factors를 그대로 베끼지 말고, **실제로 돈에 영향 가는 것만** 고른다.

### ⑨ 핵심 재무 (5년 · 최소 3년) — 표 + 그래프 둘 다

4개 지표를 **표와 그래프 모두** 보여준다.

| 지표 | 왜 보는가 (카드에 한 줄로 표기) |
|---|---|
| 매출 (Revenue) | 사업이 커지고 있나 |
| 영업이익 (Operating Income) | 본업으로 돈을 버나 (+ 영업이익률 추이) |
| 잉여현금흐름 (FCF) | **진짜 남는 현금.** 이익은 조절 가능하지만 현금은 어렵다 |
| 부채 (Total Debt) | 갚을 수 있나 (+ 순부채/EBITDA 배수) |

규칙:
- 표에는 **연도별 증감률(YoY %)**을 같이 넣는다
- 그래프는 아티팩트 안에 그린다 (4개 지표 각각 또는 2×2 그리드)
- **각 지표마다 출처를 단다** (모드 B면 페이지까지)
- 이익과 FCF가 크게 벌어지면 → **반드시 한 줄 경고**를 단다 ("영업이익은 늘었는데 FCF는 줄었습니다. 이유를 확인해야 합니다.")

### ⑩ 내가 아직 모르는 것 (마무리)

이 카드로 답이 안 나온 질문 2~3개. 사용자가 다음에 뭘 파야 하는지 알려주는 부분.
> 예: "디즈니+가 언제 흑자로 돌아서는지는 이 자료로는 알 수 없습니다. 최근 어닝콜을 봐야 합니다."

## 워크플로우

### Step 1 — 입력 확인

- 티커/기업명 파악 → 미국/한국 판별
- 업로드 자료 있나? → 모드 A / B 결정
- 모드 A면: 카드 하단에 "10-K 업로드하면 페이지 출처까지 나옵니다" 안내 한 줄

### Step 2 — 자료 수집

**모드 A (웹검색)**
```
web_search: "{기업명} 사업 모델 매출 구성"
web_search: "{TICKER} revenue by segment {최근연도}"
web_search: "{TICKER} 10-K annual report"    (미국)
web_search: "{기업명} 사업보고서 DART"        (한국)
web_search: "{TICKER} free cash flow total debt 5 year"
```
- 1차 소스(SEC EDGAR, DART, IR 페이지)를 우선한다. 블로그·커뮤니티는 쓰지 않는다.
- 값이 소스마다 다르면 → 1차 소스를 따르고, 차이가 크면 카드에 표시한다.

**모드 B (업로드)**
- 업로드 문서를 먼저 끝까지 훑는다
- 매출 구성 → Segment 주석 / 사업부문 주석
- 재무 → 재무제표 본문 + 현금흐름표
- FCF = 영업활동현금흐름 − 자본적지출(CapEx). **계산 과정을 카드 각주에 남긴다.**
- 페이지 번호를 정확히 기록한다

### Step 3 — 계산

수치 계산(YoY, 비중, FCF, 배수)은 **반드시 코드 실행으로** 한다. 암산하지 않는다.

### Step 4 — 카드 생성

- 위 ①~⑩ 순서 그대로, **아티팩트 하나**로
- 형식: HTML (그래프·다이어그램 포함) 권장
- 스타일: 흰 배경, 검정 텍스트, 파랑 강조. 미니멀. 인쇄해도 읽히게.
- **한 화면 스크롤로 훑을 수 있어야 한다.** 길면 압축한다.

### Step 5 — 마무리 한 줄

카드 아래 채팅에 짧게:
- 모드 A였으면 → 업로드 안내
- 특이사항 1개 (있으면)
- 길게 쓰지 않는다. 카드가 본체다.

## 자주 하는 실수 (하지 말 것)

| 실수 | 왜 안 되나 |
|---|---|
| 2분 드릴에 업계 용어 사용 | 초등학생이 이해 못 하면 실패 |
| 돈 버는 구조를 텍스트로 나열 | 그림이어야 한다. 그게 이 스킬의 차별점 |
| 지역별 매출 생략 | 환율·지정학 리스크가 안 보인다 |
| 리스크 5개 이상 나열 | 3개. 다 읽지 않는다 |
| 웹검색인데 페이지 번호 적기 | **가장 위험한 실수.** 신뢰가 무너진다 |
| 숫자 추정 | 모르면 `확인 필요` |
| 영어로만 표기 | 반드시 한국어 (+영문 병기) |
